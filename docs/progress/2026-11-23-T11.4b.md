- **Brief:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 4 (the interactive prototype), E1a, E1b; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
- **What:** the Messages page for both roles (`views/messages.py`, after Clients for a coach and Coach and sharing for a gymer): the user's relationships, active first and ended ones marked, and the chosen thread in a browser component (`st.components.v2`; `views/components/messages.mjs` and `messages.css`, our own code read from the repo) inside an `st.fragment` keyed by the thread. Each run of the fragment reads the thread from the store and, for an active relationship with the socket mounted, a secret set and the page at an allowed address (`st.context.url`), mints a token for the acting user (`src/realtime/page.py`) into the component's `data` only. The component opens the socket on the page's own host, sends the token first, merges the store read and the pushes by ID, shows text with `textContent`, asks for a rerun of the fragment two minutes before the token expires and sends the new token with its last ID on the open socket, answers `more`, reconnects after a drop with a doubling wait (a new token first when the old one is about to expire), stops after three refusals in a row, caps a message at 1,000 characters (code points) and shows "not sent" and other-thread notices. The chat app of T11.4a is mounted on Streamlit's own server: `serve.py` (`app = st.App("app.py", routes=server.chat_routes(...), lifespan=server.quiet_library_logs)`), so `streamlit run serve.py` serves the pages and the socket at `/realtime/ws` from one process and port; `streamlit run app.py` alone mounts none, and the page then shows the thread read-only and says how to start. `src/realtime/server.py` now holds `chat_routes()`, the allowed origins (the local hosts on the port Streamlit serves, plus `config.CHAT_PUBLIC_ORIGINS`, empty), the lifespan hook that routes uvicorn's loggers through the JSON formatter once the server has started, and `mounted()`; `create_app()` takes the store path and the origins as functions, read per socket; `python -m src.realtime`, `main()`, `--store`, `--port`, `CHAT_SERVER_HOST`/`PORT`, `CHAT_ALLOWED_ORIGINS`, the `chat_server` log event and `configure_logging(with_tracing=False)` are gone. `src/config/realtime.py`: the mount path, the local hosts, the public origins, the renewal and reconnect settings. Demo mode seeds three made-up messages between the coach and Sam (`src/demo.py`). Texts in English and German (`src/i18n/thread.py`; the page's title in `shared.py`). Docs: `.claude/rules/security-privacy.md`, `docs/SECURITY.md`, `docs/ARCHITECTURE.md` (layout, D24 revised, section 16), `docs/TESTING.md`, `docs/DEPLOYMENT.md` ("Real-time messages"), `docs/PRD.md`, `CLAUDE.md`, the README, `.streamlit/secrets.toml.example`. Tests: `tests/test_app_messages.py`, `tests/test_messages_component.py` with `tests/js/messages.test.mjs` (Node's built-in runner), `tests/test_realtime_server.py` (rewritten), `tests/test_realtime_app.py`, `tests/test_realtime_tokens.py`, `tests/test_config_package.py`, `tests/test_account.py`.
- **Why:** Research confirmed that `st.components.v2` holds a socket (the default export runs again when `data` changes and cleans up only at unmount, so a fixed key keeps one socket across token renewals; a trigger carries the fragment's ID, so a renewal reruns only the fragment, not the drafting on other pages), so no fallback to polling was needed. The owner then chose `st.App` over T11.4a's second process (2026-11-23): one command and process, no launcher and no store hand-off in demo mode, and the socket on the page's own origin (no 8501/8502 mismatch, and `wss://` follows an https page), which also leaves one port and one TLS certificate for a later deployment to two devices. One renderer (the component) for both the live and the read-only thread keeps text handling in one place.
- **Decisions & gotchas:** the owner's choices in the Question phase (2026-11-23): read-only without the socket; Node's built-in test runner in CI for the component's logic; the demo conversation between Alex and Sam only; then `st.App` instead of the separate process, with the ticket's fourth criterion replaced by two (the ticket's file). `streamlit run` finds an ASGI app by reading the file for `app = st.App(...)`, so a call inside a helper (as first written) served the pages with no socket: `serve.py` writes the call out, and a test runs Streamlit's own discovery on it. uvicorn sets its loggers up after `serve.py` is imported, so the routing runs in the lifespan hook; it now also covers Streamlit's own socket, whose handshake lines no longer reach stderr. The origin list stays fixed (the local hosts on the served port), not the request's own `Host`, which a page that rebinds its name to this machine would match. The picker's labels are worked out in the run, as Streamlit may call `format_func` outside it. AppTest runs no JavaScript, so the page tests read the component's `data` and key. With one process, restarting the server restarts the pages' sessions (and, in demo mode, the made-up store), so the live reconnect check is a sleep instead (`docs/TESTING.md`). Known limit: sharing Streamlit's uvicorn, a frame up to Streamlit's own message size limit is read before the socket's 8 KB cap closes it (`docs/SECURITY.md`).
