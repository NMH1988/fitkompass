### T11.11 (P1) The coach's own video link and a click counter (S) · status: todo · issue not yet created
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): E1b in part; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none; beyond the brief (owner's request, 2026-11-19) for the counter.
**Depends on:** T11.4, T11.8
**Acceptance criteria** (proposed by Claude, 2026-11-19; for the owner's approval)
- [ ] A coach adds a video link to their recipe; a link that is not https or not on the allowed hosts in config is refused - parametrised tests.
- [ ] The recipe's video button goes through the chat server's redirect, which adds one to that recipe's count, stored as a row with the recipe only (no user ID and no time, so the table is no timed log of one client's clicks), and redirects only to the link stored for that recipe (an unknown recipe or any other target gets a 404), and catches every exception like T11.4's socket handler (a fixed answer, diagnostic fields only, no traceback) - `TestClient` tests, an open-redirect attempt among them, and T11.4's canary test on a real `uvicorn.Server` extended to a redirect that raises.
- [ ] The coach sees each recipe's click count, and the gymer's button says, in English and German, that the coach sees how many times it was clicked - AppTest.
- [ ] The counts table is named in `my_data.delete_user_data()` (deleted with its recipe) and in the coach's export, and in `.claude/rules/security-privacy.md`'s list of stored data; `docs/SECURITY.md` records two known limits: with one client a count shows that client clicked, and the redirect takes no token, so anyone who can reach the local server, or any web page open in the same browser, can raise a count, and guessing a recipe's ID be sent to its stored link (accepted by the owner while the app runs locally only, 2026-11-19, with the fixes of code review round 7 of T11.1; a public deployment needs a token or a signed link) - store tests (the coach's export holds no click time), review.
- [ ] `docs/PRD.md` AC-52 holds; `code-reviewer`, `/security-review` (a redirect), and their reports on the PR.
