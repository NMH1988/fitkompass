### T11.4 Real-time messages: the WebSocket server, the signed token and the browser component (L) · status: todo · issue not yet created
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 4 (the interactive prototype), E1a, E1b; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.3
**Acceptance criteria** (proposed by Claude, 2026-11-19; for the owner's approval)
- [ ] A coach and their active client each have a Messages page whose thread shows a new message from the other side without a reload (D24) - a FastAPI `TestClient` WebSocket test with two connections, and the owner's live check in two browsers (demo mode).
- [ ] The server accepts a connection only with a valid token, sent as the socket's first message and never in the URL: a bad signature, an expired token, another user's or another thread's token, a missing token, a token in the query string or a foreign `Origin` is refused before any message is read - parametrised tests.
- [ ] The token holds only the keyed user ID, the thread and the expiry; the token and its secret are read only through config, never logged or shown; the time to live is in `src/config/` - tests, a canary test that no log line (the app's or uvicorn's) holds a token, and `tests/test_client_rules.py`-style scans if a new secret is added.
- [ ] The server binds to localhost only, runs uvicorn with its access log off and its `uvicorn.error` logger at WARNING (at INFO it logs every WebSocket handshake with the client's address), keeps the thread ID out of the socket's path, and logs no message text, token or address; a message the store refuses gives the sender a fixed error, never the reason; the socket handler and the redirect catch every exception, close or answer with a fixed code, and log only diagnostic fields (as `llm.error_diagnostic()`), so uvicorn never writes a traceback (it logs an uncaught error's traceback at ERROR, which could hold a message) - tests, among them one on a real `uvicorn.Server` bound to localhost (FastAPI's `TestClient` never runs uvicorn's protocol code) with a canary over every log line it writes, for normal and refused traffic and for a handler that raises an error with the canary in its message.
- [ ] The component bundles its own JavaScript (no request to a CDN); the demo mode's seed messages are synthetic text we wrote - review, AppTest.
- [ ] How to start both processes is in `CLAUDE.md` ("Commands"), the README and `docs/DEPLOYMENT.md` - review.
- [ ] The new dependencies (FastAPI, uvicorn and what they pull in) pass `tests/test_dependency_licences.py` and `pip-audit` - CI; `code-reviewer`, `/security-review` (a new network entry point), `compliance-reviewer` (a new dependency and service), and their reports on the PR.
**Notes:** the component uses `st.components.v2` (Streamlit 1.66); the Research phase reads its version's docs. Risk: Streamlit reruns and the socket's lifetime; the component keeps the socket and sends the page only what it needs. The message notifications of T11.3 are pushed over the same socket.
