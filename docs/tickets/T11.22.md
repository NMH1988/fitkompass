**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): E1a (the food log's lookups, the drafts and the chat's food tool match the food named, T11.10's photo and voice drafts included); Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none. **Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-26; reworded after code review rounds 2 and 3 of NMH1988/fitkompass#52, the same day, with the same aim: no match on a word that is not the food)
- [ ] `src/tools/food.py` counts a USDA name as a match only when its head shares a word with the query: the head is the part before the first comma, extended by the next part for as long as the last part taken is a USDA group word (a fixed list in `config`, measured on the table: today nuts, fish, crustaceans, seeds, restaurant and the restaurant names' cuisines, Chinese and Latino; T11.20 adds SR Legacy's, such as beverages, spices and cereals), as USDA names some foods by their group first ("Nuts, almonds, whole, raw", "Fish, salmon, ...", "Crustaceans, shrimp, ...", "Restaurant, Chinese, fried rice, without meat"); words compared after the plural folding of `_normalise()`; preparation and state words (a fixed list in `config` under a name of its own, apart from `FORM_WORDS`: boiled, cooked, raw, fried, grilled, baked, roasted, steamed, frozen, drained, fresh, dried) never count as the shared word; the score and its threshold (`config.FOOD_MATCH_MIN_SCORE`) stay; a query that fails the check gets "not found" with its suggestions, as an unknown food does now - unit tests on today's table: "boiled eggs" never matches kale and gets egg foods first among its suggestions; "salt" never matches "Tomato, sauce, canned, with salt added", nor "olive oil" "Anchovies, canned in olive oil, with salt, drained" (today's table has no olive oil); nor "meat" "Chicken, wing, meat and skin, raw"; "rolled oats", "chicken breast", "cottage cheese", "green beans", "almonds" (the nuts, never almond butter), "walnuts", "salmon", "shrimp" and "tuna" still match what they match today, and the head rule never blocks "fried rice" from "Restaurant, Chinese, fried rice, without meat" (its head holds both words); the module's docstring no longer promises that small typos find the food (they do not today); whether "boiled eggs" should then match an egg food (its egg names score 65.8 to 70.8, below the threshold) is decided in the Question phase and pinned by the test.
- [ ] Every path that decides a match gets the check: `lookup_food_nutrition` (the chat's tool, the drafts' matching in `src/drafting.py` for T11.5 and T11.10, the meal plan tool) and the USDA API fallback, which checks its own results against its own threshold (`src/tools/food_api.py`); a local "not found" still asks the API with the owner's key set - the existing tests of T4.3, T9.9, T11.5 and T11.10 pass, and a fixed list of everyday names (which T11.20 reuses) is checked against the table, each with the food it should match or "not found".
- [ ] The owner's evaluation run (`python -m scripts.run_evaluation`) checked with `scripts.check_eval_baseline` (the food questions' tool results may change).
- [ ] A progress entry; no compliance run is needed, as no data collected, stored or sent changes (its PR description says so).
