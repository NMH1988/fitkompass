**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-26; reworded after code review round 2 of NMH1988/fitkompass#52, the same day, with the same aim: no match on a shared cooking word alone)
- [ ] `src/tools/food.py` counts a USDA name as a match only when its head (the part before the first comma, the food itself in USDA's names) shares a word with the query, words compared after the plural folding of `_normalise()`; preparation and state words (a fixed list in `config` under a name of its own, apart from `FORM_WORDS`: boiled, cooked, raw, fried, grilled, baked, roasted, steamed, frozen, drained, fresh, dried) never count as the shared word; the score and its threshold (`config.FOOD_MATCH_MIN_SCORE`) stay; a query that fails the check gets "not found" with its suggestions, as an unknown food does now - unit tests on today's table: "boiled eggs" never matches kale and gets egg foods first among its suggestions; "salt" never matches "Tomato, sauce, canned, with salt added", nor "olive oil" "Anchovies, canned in olive oil, with salt, drained" (today's table has no olive oil); "rolled oats", "chicken breast", "cottage cheese" and "green beans" still match what they match today; whether "boiled eggs" should then match an egg food (its egg names score 65.8 to 70.8, below the threshold) is decided in the Question phase and pinned by the test.
- [ ] Every path that decides a match gets the check: `lookup_food_nutrition` (the chat's tool, the drafts' matching in `src/drafting.py` for T11.5 and T11.10, the meal plan tool) and the USDA API fallback, which checks its own results against its own threshold (`src/tools/food_api.py`); a local "not found" still asks the API with the owner's key set - the existing tests of T4.3, T9.9, T11.5 and T11.10 pass, and a fixed list of everyday names (which T11.20 reuses) is checked against the table, each with the food it should match or "not found".
- [ ] The owner's evaluation run (`python -m scripts.run_evaluation`) checked with `scripts.check_eval_baseline` (the food questions' tool results may change).
- [ ] A progress entry; no compliance run is needed, as no data collected, stored or sent changes (its PR description says so).
