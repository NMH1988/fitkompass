### T11.23 (P1) A voice note's speech always reaches the guard, with NONE only for no speech (S) · status: todo · issue NMH1988/fitkompass#54
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): E3 (a gymer who speaks about an injury or a health problem reaches the guard, whose refusal the page shows, not "nothing to draft"), E1a; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none. Found in T11.10's live check and code review round 11 of NMH1988/fitkompass#46 (owner's request, 2026-11-26).
**Depends on:** T11.10, O27
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-26; criteria 2 to 4 made exact after code review round 6 of NMH1988/fitkompass#52, 2026-11-27, with the same aim)
- [ ] The owner's new text of `src/prompts/media_voice_system.md` (O27) asks for NONE only when the recording holds no intelligible speech (silence, noise) or its transcript would not fit `config.MEDIA_TEXT_MAX_CHARS`; every other speech, about food or not, is transcribed, so the input guard and the domain guardrails decide on it, as T11.10's criteria order; its version (`prompt_media`) changes, consent (c) does not - a test that reads the instruction's lines that name NONE and compares them with the approved conditions, so a "nothing relevant" rule cannot come back unseen.
- [ ] A voice note read as NONE and a transcript the guard passed with no entry found by the draft model end differently: the voice note's NONE gets an outcome of its own (e.g. `no_speech`), a new value of the `media_draft` line's existing `code` field (no new log field, so the allowlist does not change), with its own message on the page ("The AI heard no speech it could write down in this recording", which also covers a transcript too long for `config.MEDIA_TEXT_MAX_CHARS`), in English and German; a photo read as NONE, an empty file and a run whose entries were all dropped keep `nothing` and today's message ("no food, weight or workout to draft"), with the dropped note as today - graph tests and AppTests for each of these endings, and the log canary tests.
- [ ] The owner's live check: the T11.10 injury recording (synthetic, Piper) played again gives the page's refused notice (`media.refused`, the fixed warning T11.10 shows for every guard refusal) with a `guard_rejected` line in the log, or, if the guard passes its wording, no card with `nothing` in the log; a recording of silence gives the "no speech" message with the new code - recorded in `docs/TESTING.md`.
- [ ] A progress entry and a compliance run: after this change every speech the guard passes reaches the draft model, food or not, which changes what is sent to a model (`.claude/rules/workflow.md`); the photo and the transcript are kept as T11.10 keeps them.
**Notes:** In T11.10's live check (2026-11-26) a synthetic voice note about a knee injury ended `nothing`, with no guard line in the log. Code review round 11 of NMH1988/fitkompass#46 found that the log cannot tell a NONE reading from a passed transcript with no entry, and that the voice instruction's last line ("When no relevant content is available, return exactly the uppercase string: NONE.") lets the model drop speech it judges irrelevant, before the guard, so a gymer who speaks of an injury may see "nothing to draft" instead of the guard's refusal. The photo instruction's NONE ("no clearly identifiable food or beverages") is left as it is: a photo with no food has nothing for the guard to read. The instruction is the owner's text (O19, `.claude/rules/workflow.md`: the owner writes prompts first), hence O27.
