### T11.3 Coach-client messages in the store (M) · status: todo · issue not yet created
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 2 (the database the agent's tools read), Case 2 step 4 in part, E3; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.2 (order only)
**Acceptance criteria** (proposed by Claude, 2026-11-19; for the owner's approval)
- [ ] A migration adds a `messages` table (thread = the coach-client relationship, sender, time, text with a length limit from config); a message is written only by a side of an active relationship, and a thread is read only by its two sides; every other case gets the same `NotFound` and writes no row - the new functions in `tests/test_store_access.py`'s refused-cases matrix, or a group of their own there. The Question phase sets, with the owner, how a thread read fits the store's rule that every read of another user's data goes through `access.authorised_read()` and every coach read is audited (messages belong to no sharing scope, so `open_shares` cannot decide it): a relationship-based check like `users.display_name_of()` or a new scope, whether a read is audited (an audit row for every message the server pushes would flood the log), and who reads a thread after the relationship ends; the choice is recorded in `.claude/rules/security-privacy.md` as the earlier exceptions are.
- [ ] Messages are in both sides' export and are deleted with either side's data - `tests/test_store_my_data.py` (or its equivalent) with the new table named in `my_data.delete_user_data()` and `export_user_data()`.
- [ ] A new message is a notification kind (D23), worked out from the rows, holding no text, seen only by the other side - notification tests.
- [ ] No log line or trace holds a message's text - a canary test in `tests/test_observability.py`.
- [ ] The store's connection settings let a second process (T11.4's server) read and write the same file safely (WAL and a busy timeout, or what the Research phase finds) - a test with two connections.
- [ ] `.claude/rules/security-privacy.md` ("Personal data", "The store") and `docs/SECURITY.md` name the messages; `docs/PRD.md` AC-45's store part holds - review; `code-reviewer`, `compliance-reviewer` (new stored personal data), and their reports on the PR.
**Notes:** no UI yet (T11.4 shows the thread). Every query a module constant with `?` parameters (`tests/test_store_sql_scan.py`). Messages are never sent to a model in this ticket.
