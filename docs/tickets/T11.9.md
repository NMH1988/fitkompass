### T11.9 Dish suggestions for a meal of the plan, with code checks, two pauses and a YouTube search button (L) · status: todo · issue not yet created
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 steps 1-3 (the agent's second workflow), E2a, E2b; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.7, T11.8, O20
**Acceptance criteria** (proposed by Claude, 2026-11-19; for the owner's approval)
- [ ] For a meal slot of the coach's plan, the graph (D27) offers the coach's recipes scaled to the plan's grams first and, when none fits, well-known dishes the model names from the plan's ingredients - graph tests with a scripted fake model.
- [ ] The plan reaches a model only with the gymer's consent (d) (`docs/PRD.md`, the Capstone's consents), given or withdrawn in one click, stored with the version of its text and checked again right before each model call through T11.5's consent functions; without it only the coach's recipes are offered, scaled by code, and no model is called - a graph test with a fake model that is never called.
- [ ] Every dish shown passes the code checks (ingredients in the plan or the basics list in config, grams within the plan, macros from the USDA data, the day's planned total with the dish in place not below the daily calorie floor); a dish that fails is dropped, never shown - parametrised tests, a model that proposes a food outside the plan or a made-up amount among them, and a valid single-meal dish well under the daily floor that is shown.
- [ ] The graph pauses for the gymer's pick and again for the approval to log; nothing is logged without the second - graph tests (`interrupt()` and resume), AppTest.
- [ ] A dish name the model writes passes the domain guardrails' checks (medical conditions, T9.16's diagnosis wordings) or the dish is dropped - parametrised tests.
- [ ] A dish the model named shows a "Find recipes on YouTube" button whose link is the configured search URL with the dish's name and "recipe", quoted with `quote_plus`, and whose label or help text says it opens YouTube (Google) in a new tab and searches for the dish's name; no URL from the model reaches the page; no embed, thumbnail or logo - tests of the link builder and of the page.
- [ ] A dish the model named is labelled as AI-generated in English and German (a coach's own recipe is not); the values carry the USDA credit; the masked trace and the log lines hold no plan values or dish text - AppTest, canary tests.
- [ ] `docs/PRD.md` AC-49 holds; `code-reviewer`, `/security-review` (model output to links and to the store), `compliance-reviewer`, and their reports on the PR.
**Notes:** the owner drafts the prompt (O20). The basics list (e.g. water, salt, spices with no energy in the USDA data) and the search URL live in config. An approved coach's recipe is logged through T11.8's path, so its meal items carry the `from_recipe` mark the store checks, and a rating (T11.8) is offered after it; a dish the model named is logged as plain food entries, with no recipe mark. The meal slots come from T11.7's fixed list, so no free text of the coach's reaches the model.
