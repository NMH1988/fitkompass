### T11.6 (P1) The coach's thread summaries and reply drafts (M) · status: todo · issue NMH1988/fitkompass#13
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 steps 1-3 (report generation for the coach), E2b; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.5, O21
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-19, with the choices in the Notes)
- [ ] On a thread, the coach asks for a summary of the messages of a week they pick (Monday to Sunday in `Europe/Berlin`, D21; at most a number of messages from config) or a reply draft; the draft is labelled as AI-generated in English and German and is sent only after the coach approves or edits it; a summary lives in the session only and is never stored, and a reply becomes data only when sent as a message - graph tests with a fake model, AppTest, a store test that a summary writes no row.
- [ ] A reply sent from an AI draft, edited or not, shows the gymer an "AI draft approved by the coach" label in English and German, as a weekly review does (AC-41); the message row keeps that flag, named in `.claude/rules/security-privacy.md`'s list of stored data, in both exports and deleted with the message - store tests, AppTest.
- [ ] The thread (the coach's own messages included, as they can repeat the gymer's health data) reaches the model only with that gymer's consent (b) (`docs/PRD.md`, the Capstone's consents), which the gymer gives or withdraws in one click, stored with the version of its text and checked again right before each model call through T11.5's consent functions; consent (a), for their own drafts, does not count; without (b) the request is refused with a clear message and no model call (owner's choice, 2026-11-19) - tests, one with a fake model that is never called.
- [ ] Each message of the thread, from either side, and any text the coach types into the request (a hint for the reply, say), runs through the input guard and the domain guardrails before the model call, as in T11.5; a rejected message is left out of what the model receives, so an injury or injection message never reaches a model; when messages were left out, the draft says how many, without their text, and asks the coach to read them in the thread, as one may be an injury the coach must see - parametrised tests with a fake model that never receives a rejected message, AppTest of the note.
- [ ] A summary or reply draft is offered only while the coach's relationship with the client is active, and consent (b) is given for one coach: it ends with that relationship and does not carry over to a later coach, so a former coach can never send a former client's thread to a model - store and graph tests (a former coach refused with no model call; a new coach without a new consent (b) refused).
- [ ] No log line or trace holds a message, a summary or a draft - canary tests in `tests/test_observability.py` and a case in `tests/test_tracing.py`.
- [ ] Every Sprint 3 guardrail holds for a draft (no diagnosis, no program, the calorie floor in a recommendation, refused in code by the weekly review's checks where they apply) - tests reusing T9.16's and T10.2's checks.
- [ ] `docs/PRD.md` AC-50 holds; `code-reviewer`, `/security-review`, `compliance-reviewer`, and their reports on the PR.
