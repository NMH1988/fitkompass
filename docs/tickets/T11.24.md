### T11.24 (P2) A client's name the coach types is read as the chat's reference (M) · status: todo · issue NMH1988/fitkompass#60
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 4 (the coach names a client in the chat as they would to a person), E1b (the interaction: no question back about which reference a name is), E3 (a name the coach types no longer reaches the model); Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T9.17 (done), T11.6a (done, NMH1988/fitkompass#47; order only, as both change the coach's chat in `views/chat.py` and the client tools)
**Acceptance criteria** (proposed by Claude on 2026-11-27 and approved by the owner on 2026-11-28, with (a) chosen for which words are read; the other open choices in the Notes, for the Question phase)
- [ ] **A name becomes the chat's reference before the question reaches the model.** In a coach's chat, each client's name the coach types in a question is replaced, in the text the model receives, by that client's reference in this chat (`client-N` of `ClientRefs`, `src/tools/coach_clients.py`), given then if the client has none yet, so a question such as "Summarize what Sam and I wrote this week" can be answered without `list_my_clients` first. The names matched are those of every client the coach has had, active or ended (the list `preferences.client_names()` reads); an ended client's reference gets the tools' same "not found" - unit tests of the matcher; a graph test with a fake model whose first call receives the reference and calls `get_client_thread` and `get_client_week` with it, both found.
- [ ] **The matcher's cases.** A name matches as whole words, all its words in a row, without case (as `preferences.names_in()`), and also typed without its accents ("Zoe" for "Zoë"); with the English possessive ("Sam's" becomes "client-1's") and the German genitive ("Sams Nachrichten"), the latter only when "Sams" is not itself a client's name; when names overlap ("Sam" and "Sam Lee") the longest is replaced first; a name inside a code span, a link or a URL is replaced too, so no form of the question carries it to the model; a name two of the coach's clients share is left as typed, and the model then asks which client is meant, as today; a word that only contains a name ("Samuel", "maximum" for "Max") is never replaced; besides the full display name, a single word of it is read as the client when no other client of the coach has that word in their name, it is typed with a capital first letter and it has at least two letters ("Sam" for "Demo gymer Sam", never "Demo" or "gymer", which every demo client has) - parametrised unit tests for each case, with benign questions that must come out unchanged.
- [ ] **The coach sees what was read.** Under the question, the page writes in code, never left to the model, one line per matched word naming whom it was read as ("Sam: read as your client Demo gymer Sam"), in English and German, so a wrong match is seen at once; a question with no match shows no line - AppTest in both languages, with a match, two matches and none.
- [ ] **What is kept and shown.** The question kept in the chat's memory and sent again in later turns (`src/agent/memory.py`) holds the reference, never the name; the page shows the question as the coach typed it, and the answer with names, as today (`with_client_names()`); the PDF summary follows the owner's choice (2) below; "New chat" forgets the references and the mapped questions together - AppTest (the shown question, a second turn whose model input holds no name), a PDF test.
- [ ] **The checks stay as they are.** The input guard and the domain guardrails check the question as typed, before the mapping, and a question they refuse reaches no model; a preference that names a client, by name or by reference, is still refused (`preferences.check_preference()`); the food tool's check against the coach's clients' full display names (`src/tools/food_api.py`) stays - the existing tests pass unchanged, plus a test of a mapped question at the length limit.
- [ ] **No name reaches the model.** `test_no_name_or_user_id_reaches_any_message_of_the_coach_s_chat` gets a case where the coach types a canary display name in the question: no message of the turn, the system prompt, the question, a tool call or a tool result, holds it; the same for a second turn of the same chat; no log line or trace holds the name or the mapping (`tests/test_observability.py`, `tests/test_tracing.py`).
- [ ] **Docs.** `docs/SECURITY.md` (the client tools' row: its limit "the model's own text may still name a client if the coach typed the name in the question") and `docs/TESTING.md` (known limit 9) say what is left: a name two clients share, a name typed in a form the matcher does not read (a nickname, a misspelling), and a name inside a client's message in a thread result (T11.6a, which consent (b)'s text names); texts in English and German for any line the page adds; a progress entry.
- [ ] `code-reviewer` and `compliance-reviewer` (what goes into model messages changes: fewer names), their reports on the PR; `/security-review`, as the coach's prompt input changes.

**Needs the owner** (Claude's recommendation first):
1. **Which words are read as a client.** The owner chose (a) on 2026-11-28, as Claude recommended (criteria "The matcher's cases" and "The coach sees what was read"). The options were: (a) the full display name, and also any single word of it that no other client of the coach has in their name, typed with a capital first letter and at least two letters ("Sam" for "Demo gymer Sam", but not "Demo" or "gymer", which every demo client has), and a line under the question, written by the page in code, naming whom each matched word was read as ("Sam: read as your client Demo gymer Sam"), so a wrong match is seen at once; the risk is a client whose name is an everyday word ("Will", "May") at the start of a sentence. (b) The full display name only: no wrong matches, but "Sam" is not read when the name is "Demo gymer Sam" or "Sam Müller", which is the case the live check met. (c) A client picker beside the chat that puts the client's reference into the question: exact, but one more click, and a typed name is still sent as typed.
2. **What the page and the PDF show for the question.** Recommended: the question as the coach typed it, with the name, in both (the coach's own text, read by the coach only, as today); otherwise the PDF would show "client-1" where the coach wrote a name.
