**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): E1a (the food log, the drafts, including T11.10's photo and voice drafts, and the plans find the foods people eat); beyond the brief (owner's request, 2026-11-26) for the feature itself; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.10, T11.22 (order only: the matcher's fix first), O26 (for the counted foods)
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-26; corrected after code review rounds 1 and 2 of NMH1988/fitkompass#52, the same day)
- [ ] Before anything is downloaded, the owner approves the new use in the Question phase and `docs/SOURCES.md` row 21 records it (rule 4); then `scripts/prepare_usda.py` builds `data/usda_foods.csv` from three USDA FoodData Central CSV zips downloaded by hand from USDA's download page into gitignored `data/usda/`: Foundation Foods (as now), SR Legacy (April 2018, the final release) and Survey (FNDDS 2021-2023, released 2024-10-31). It reads each file as a stream, never whole into memory; the guard against a zip bomb stays, its limit (`config.USDA_MAX_MEMBER_BYTES`, 100 MB today) set per data type from the sizes measured on the downloaded releases, with the reason in config; it prints how many foods each type gave and how many were dropped and why - unit tests on small fixture zips of each type, and one that a member over its type's limit is refused.
- [ ] Each row keeps the table's columns per 100 g and gains its data type and release; a food with no energy or no protein, carbohydrate or fat value is dropped; when two foods have the same name, the one kept is Foundation's, then SR Legacy's, then FNDDS's; the Foundation release stays the one in today's table (2026-04-30), as `scripts/prepare_usda.py` keeps the latest publication of each name and a newer release can drop an FDC ID (a newer release is a change of its own, which checks the stored suggested foods' IDs first); so every food of today's table stays with its FDC ID and name; Branded and Experimental foods are never read (`.claude/rules/copyright.md`, rule 10) - unit tests, and one that every FDC ID and name of today's table is in the new one.
- [ ] Every user of the table reads the larger one: the food log's picker, the drafts' matching (`src/drafting.py`), the chat's `lookup_food_nutrition` and the USDA API's fallback, the meal plan, the recipes and the suggested foods; the names the current tests match still match a sensible food (the fixed list of everyday names from T11.22, checked against the new table, with names that FNDDS's long heads could catch, such as "meat" and "tomato sauce" against "Pasta with tomato-based sauce and meat, home recipe"; SR Legacy's group words added to T11.22's list) - unit tests, and the owner's evaluation run (`python -m scripts.run_evaluation`) checked with `scripts.check_eval_baseline`.
- [ ] Every value is credited to the dataset it came from, wherever the table is credited today: the source line under each table value in the app and the PDF, in English and German (`src/config/nutrition.py`, `src/i18n/food.py`); the food caption that says "Foundation Foods table" (`src/i18n/food.py`); `config.USDA_CITATION` and `config.USDA_CHANGES` (the CSV's header, `ATTRIBUTION.md`, the app's source page in `src/rag/sources.py`, the PDF); the release check (`RELEASE_IN_CREDIT` and `read_usda_release()` in `src/tools/food.py`, which read one release today and must read three); the tool descriptions and messages the model reads (`src/tools/registry.py`, `src/tools/food.py`, `src/tools/meal_plan.py`); and `docs/PRD.md`, `docs/ARCHITECTURE.md`, `README.md`, `docs/SOURCES.md` and `ATTRIBUTION.md` (regenerated by `scripts/generate_attribution.py`, naming the three data types and USDA's suggested citation as the home page gives it on the check date); nothing suggests USDA endorses the app - tests: a value from each data type shows that type's credit; the release check reads the three releases; `tests/test_attribution.py`.
- [ ] A food named by count ("two eggs", "a banana") gets grams from USDA's own portion weights (the food portions of the three data types, Foundation's where it has them, kept in a small committed file beside the table, e.g. "1 large egg = 50 g", named in the credits and in the size measurement): the drafting schema gains a count and a portion word, as the owner's text for it says (O26), and code multiplies the count by the portion's grams when the matched food has that portion, or by its one default portion; with no portion that fits, the card's grams stay empty as now; the card shows how the grams were worked out (e.g. "2 × large (50 g)") - unit tests (a count with a named portion, a count with only a default portion, a count with none, grams stated in the message winning over a count), and the live check's "two boiled eggs" run end to end on the built table; whether a Foundation food with no portion may borrow the portion of an SR Legacy or FNDDS food with the same head is decided in the Question phase; added by the owner on 2026-11-26, after T11.10's live check.
- [ ] What is already stored keeps working: logged entries, plans and recipes store the FDC ID, the name and the nutrients, so a change in the table changes no stored row; suggested foods store only the FDC ID (`food_suggestion_items`) and read the name and nutrients from the table (`with_nutrients()`, `log_suggested()`), which works because every food of today's table stays with the Foundation release kept (criterion 2) - tests: a stored entry whose food is not in the table still shows; a suggested food of today's table still shows and logs.
- [ ] The table still loads once per process and the pages that list every food stay usable: the load time, the committed file's size, and the time of the Today picker and of a draft card form with several food cards (each card lists every name) are measured and recorded in `docs/TESTING.md`, and the owner checks typing a name in both on their machine (live check).
- [ ] A compliance run (data that is not our own changes), its findings handled as `.claude/rules/workflow.md` says; a progress entry.
**Notes:** Seen in T11.10's live check (2026-11-26): the local table holds 328 Foundation Foods, so many foods on a draft card had no match, and the gymer could only pick an unrelated food from the list. The USDA pages read on 2026-11-26 (the home page, the FAQ, the data documentation and the download page) say FoodData Central data are public domain under CC0 1.0, list SR Legacy's source as USDA and FNDDS's as USDA's Foundation Foods and SR Legacy, and give no third-party or redistribution note for either; the home page asks to list FoodData Central as the source. Both types were already allowed for the USDA API (`docs/SOURCES.md` row 21, T9.9), so this is a new use of an approved source, not a new source, but rule 4 still asks for the record and the owner's approval. The pages give no food counts: SR Legacy has about 7,800 foods and FNDDS about 5,000, to be confirmed when the table is built. The download page gives FNDDS's CSV zip as about 200 MB zipped and 1.6 GB unpacked, which looks large for about 5,000 foods (it may count every nutrient row); the real sizes are measured on the download, and the zip is never committed. FNDDS names are long ("Pasta with tomato-based sauce and meat, home recipe"), so the matching's thresholds in `src/config/nutrition.py` may need tuning; the evaluation run shows whether the chat's food answers change. Food names stay in English, as now. The counted foods: in the same live check a voice note's "two boiled eggs" gave a card with no grams, as the drafting schema takes grams only from an amount stated in g or kg and the Foundation Foods table has no portion weights; the schema's field descriptions are prompt text, so the owner writes them first (O26). A portion the model names is matched in code against the food's own portions only, never taken as grams from the model. "Foundation Foods" appears in about 25 files today (code, texts, tests and docs); the criterion on credits lists those that credit or describe the table, and the build's Research phase finds the rest.
