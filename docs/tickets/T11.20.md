### T11.20 (P1) A larger USDA food table: SR Legacy and FNDDS beside Foundation Foods (M) · status: todo · issue NMH1988/fitkompass#49
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): E1a (the food log, the drafts and the plans find the foods people eat), Case 4 step 4 in part (T11.10's photo and voice drafts match more foods); beyond the brief (owner's request, 2026-11-26) for the feature itself; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.10, T11.22 (order only: the matcher's fix first), O26 (for the counted foods)
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-26)
- [ ] `scripts/prepare_usda.py` builds `data/usda_foods.csv` from three USDA FoodData Central CSV zips downloaded by hand from USDA's download page into gitignored `data/usda/`: Foundation Foods (as now), SR Legacy (April 2018, the final release) and Survey (FNDDS 2021-2023, released 2024-10-31); it reads them as streams, so the FNDDS zip (about 1.6 GB unpacked) is never read into memory, and prints how many foods each type gave and how many were dropped and why - unit tests on small fixture zips of each type.
- [ ] Each row keeps the table's columns per 100 g and gains its data type; a food with no energy or no protein, carbohydrate or fat value is dropped; when two foods have the same name, the one kept is Foundation's, then SR Legacy's, then FNDDS's; Branded and Experimental foods are never read (`.claude/rules/copyright.md`, rule 10) - unit tests.
- [ ] Every user of the table reads the larger one with no other change: the food log's picker, the drafts' matching (`src/drafting.py`), the chat's `lookup_food_nutrition` and the USDA API's fallback, the meal plan, the recipes and the suggested foods; the names the current tests match still match a sensible food (a fixed list of everyday names, checked against the new table) - unit tests, and the owner's evaluation run (`python -m scripts.run_evaluation`) checked with `scripts.check_eval_baseline`.
- [ ] A food named by count ("two eggs", "a banana") gets grams from USDA's own portion weights (SR Legacy's and FNDDS's food portions, kept in a small committed file beside the table, e.g. "1 large egg = 50 g"): the drafting schema gains a count and a portion word, as the owner's text for it says (O26), and code multiplies the count by the portion's grams when the matched food has that portion, or by its one default portion; with no portion that fits, the card's grams stay empty as now; the card shows how the grams were worked out (e.g. "2 × large (50 g)") - unit tests (a count with a named portion, a count with only a default portion, a count with none, grams stated in the message winning over a count); added by the owner on 2026-11-26, after T11.10's live check.
- [ ] What is already stored keeps its values: logged entries, plans, recipes and suggested foods store the FDC ID, the name and the nutrients, so a food that leaves or changes in the table changes no stored row - a test with a stored entry whose food is no longer in the table.
- [ ] The table still loads once per process and the Today picker stays usable: the load time and the committed file's size are measured and recorded in `docs/TESTING.md`, and the owner checks typing a name in the picker on their machine (live check).
- [ ] `docs/SOURCES.md` row 21 records SR Legacy and FNDDS in the local table, their releases, the licence line read on USDA's own pages and its check date, and the owner's approval (rule 4); `ATTRIBUTION.md` is regenerated (`scripts/generate_attribution.py`) and names the data types and USDA's suggested citation as the home page gives it on the check date; the app's own source text for the table (`src/rag/sources.py`) and the comments that say "Foundation Foods" only are updated; nothing suggests USDA endorses the app.
- [ ] A compliance run (data that is not our own changes), its findings handled as `.claude/rules/workflow.md` says; a progress entry.
**Notes:** Seen in T11.10's live check (2026-11-26): the local table holds 331 Foundation Foods, so many foods on a draft card had no match, and the gymer could only pick an unrelated food from the list. The USDA pages read on 2026-11-26 (the home page, the FAQ, the data documentation and the download page) say FoodData Central data are public domain under CC0 1.0, list SR Legacy's source as USDA and FNDDS's as USDA's Foundation Foods and SR Legacy, and give no third-party or redistribution note for either; the home page asks to list FoodData Central as the source. Both types were already allowed for the USDA API (`docs/SOURCES.md` row 21, T9.9), so this is a new use of an approved source, not a new source, but rule 4 still asks for the record and the owner's approval. The pages give no food counts: SR Legacy has about 7,800 foods and FNDDS about 5,000, to be confirmed when the table is built. FNDDS names are long ("Pasta with tomato-based sauce and meat, home recipe"), so the matching's thresholds in `src/config/nutrition.py` may need tuning; the evaluation run shows whether the chat's food answers change. Food names stay in English, as now. The FNDDS zip is about 200 MB: the owner downloads it; it is never committed. The counted foods: in the same live check a voice note's "two boiled eggs" gave a card with no grams, as the drafting schema takes grams only from an amount stated in g or kg and the Foundation Foods table has no portion weights; the schema's field descriptions are prompt text, so the owner writes them first (O26). A portion the model names is matched in code against the food's own portions only, never taken as grams from the model.
