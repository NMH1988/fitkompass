### T11.4a Real-time messages, part 1: the chat server and its signed token (M) · status: todo · issue NMH1988/fitkompass#10
**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 4 in part (the interactive prototype's server side), E1a; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.3
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-19, as T11.4's, split by the owner the same day; the choices in the Notes)
- [ ] A FastAPI app with uvicorn (D24), its code under `src/` (e.g. `src/realtime/`) so the scans of `tests/test_client_rules.py`, `tests/test_comment_history.py` and `tests/test_observability.py` cover it (or those scans gain its path), its logging set up through `observability.configure_logging()`, delivers a message one side sends to the other side's open socket and stores it through `src/store/` (T11.3) - a FastAPI `TestClient` WebSocket test with two connections, the existing scans, a test that the server's process uses the allowlisted JSON logs.
- [ ] The server accepts a connection only with a valid token, sent as the socket's first message and never in the URL: a bad signature, an expired token, another user's or another thread's token, a missing token, a token in the query string or a foreign `Origin` is refused before any message is read. While a socket stays open, a new token sent on it is verified like the first (another user's or thread's token closes the socket); the server closes a socket whose token expired unrenewed, and checks the recipient's access in the store before each push (a message or a notification), so nothing reaches a side once the relationship ends or access is lost; with each token it takes the ID of the last message the page shows and first sends the later messages of the token's own thread only, read through the store's authorised read (a made-up ID returns nothing extra), at most a number from config at once - parametrised tests, an expiry, a renewal and a relationship ending while a socket is open among them, a catch-up test, and a test that a token minted for one user cannot act as another.
- [ ] The token holds only the keyed user ID, the thread and the expiry, and lives 15 minutes (`src/config/`); the token and its secret are read only through one config function from `.streamlit/secrets.toml` or an environment variable, never hardcoded, logged, shown or put in a test, issue, PR or commit - tests, a canary test that no log line (the app's or uvicorn's) holds a token, and `tests/test_client_rules.py`-style scans for the new secret.
- [ ] The server binds to localhost only, runs uvicorn with its access log off and its `uvicorn.error` logger at WARNING (at INFO it logs every WebSocket handshake with the client's address), keeps the thread ID out of the socket's path, and logs no message text, token or address; a message the store refuses gives the sender a fixed error, never the reason; the socket handler catches every exception, closes with a fixed code and logs only diagnostic fields (as `llm.error_diagnostic()`), so uvicorn never writes a traceback (it logs an uncaught error's traceback at ERROR, which could hold a message) - tests, among them one on a real `uvicorn.Server` bound to localhost (FastAPI's `TestClient` never runs uvicorn's protocol code) with a canary over every log line it writes, for normal and refused traffic and for a handler that raises an error with the canary in its message.
- [ ] `.claude/rules/security-privacy.md` and `docs/SECURITY.md` record: the server's acting user ID comes only from a token that verifies and was minted by the Streamlit page from `st.user` (or, in demo mode, the picker's closed list), never from anything the browser sends otherwise; the token secret's rules, like the other keys'; and the second process and its logging - review.
- [ ] The new dependencies (FastAPI, uvicorn and what they pull in) pass `tests/test_dependency_licences.py` and `pip-audit`, their licences read from their metadata - CI; `code-reviewer`, `/security-review` (a new network entry point), `compliance-reviewer` (a new dependency and service), and their reports on the PR.
**Notes:** split from T11.4 by the owner on 2026-11-19, so each PR stays reviewable: this part is the server, testable without a browser; T11.4b is the browser component and the Messages page. **The owner's choices (2026-11-19):** the token lives 15 minutes (config); if T11.4b's Research finds the component cannot hold a WebSocket reliably, the work stops and the owner chooses (fragment polling, or a chat page served by FastAPI), with no silent fallback. The message notifications of T11.3 are pushed over the same socket.
