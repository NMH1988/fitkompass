**Serves:** Capstone (`docs/BRIEF_CAPSTONE.md`): Case 2 step 4 (the interactive prototype), E1a, E1b; Sprint 3 (`docs/BRIEF_SPRINT3.md`): none; Sprint 2 (`docs/BRIEF.md`): none.
**Depends on:** T11.4a
**Acceptance criteria** (proposed by Claude and approved by the owner, 2026-11-19, as T11.4's, split by the owner the same day; the choices in the Notes)
- [ ] A coach and their active client each have a Messages page whose thread shows a new message from the other side without a reload; after the relationship ends both read the thread and neither can send (T11.3) - AppTest of the page, and the owner's live check in two browsers (demo mode).
- [ ] The component (`st.components.v2`) opens the socket and sends the token as its first message; it asks for a rerun of an `st.fragment` around the thread (not the whole page, so nothing else, such as drafting, runs on a timer) before the token expires, sends the new token and the ID of the last message it shows on the open socket, reconnects with a fresh token after a close it did not ask for (sleep, a server restart, a missed renewal), and keeps a stable `key`, so a new token updates it instead of mounting a new one (Research confirms this, and that a trigger inside an `st.fragment` reruns only the fragment) - a test that messages keep arriving on an untouched page after the first token's lifetime, and the owner's live check of the reconnect: with the thread open, restart the chat server, send a message from the other browser, and see it arrive without a reload.
- [ ] The component bundles its own JavaScript (no request to a CDN); the demo mode's seed messages are synthetic text we wrote - review, AppTest.
- [ ] One command starts the Streamlit app and the chat server and stops both when it ends; `streamlit run app.py` alone still works, without real-time messages, and the page says so; the command is in `CLAUDE.md` ("Commands"), the README and `docs/DEPLOYMENT.md` - a test of the launcher with the processes faked, review, the owner's live check.
- [ ] `docs/PRD.md` AC-45 holds; `code-reviewer`, `/security-review` (browser code on a socket), `compliance-reviewer` (what the page shows and runs), and their reports on the PR.
**Notes:** split from T11.4 by the owner on 2026-11-19. **The owner's choices (2026-11-19):** one launch command; if Research finds `st.components.v2` (Streamlit 1.66) cannot hold a WebSocket reliably, the work stops and the owner chooses between fragment polling and a chat page served by FastAPI, with no silent fallback. Risk: Streamlit reruns and the socket's lifetime; the component keeps the socket and sends the page only what it needs. For the Question phase (code review rounds 12-13 of T11.1): the `Origin` check and T11.11's link host assume the page is opened at `http://localhost:8501`; Research checks whether the page can read its own host at run time (e.g. `st.context`), or the docs say to open the app only at `localhost`.
**From T11.4a's reviews (2026-11-20), for the Question phase:** the page mints with `config.chat_token_secret()` only for the acting user from `st.user` or the demo picker, never puts the token in a URL, `st.query_params` or a log, and is added to the callers scan in `tests/test_realtime_tokens.py`; the component keeps the token in memory (not `localStorage` or `sessionStorage`), renders message text as plain text, de-duplicates by `id`, knows a renewal never rewinds its socket (a list rebuilt from a store read older than what the socket already pushed gets the missing messages only from a new socket, whose first `after_id` is taken as it is, or a new read of the thread), reads `ready` as "every stored message up to here was sent" (a push or a notification may come before it), answers `more` by an `auth` frame with its new last ID or a read of the thread, and caps the text at `MESSAGE_MAX_CHARS` before sending (a frame over `CHAT_MAX_FRAME_BYTES` closes the socket instead of `not_sent`); the Messages page carries the made-up-data note and says the messages are stored, read by the other side also after the end, and removed by either side's delete (EN/DE); the launcher starts Streamlit on 8501 or fails (the `Origin` allowlist), makes demo mode's store folder and passes `--store` to the chat server.
